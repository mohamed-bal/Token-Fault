# Threat Model

- **Scope:** TokenFault v0.1.0 (proxy, mock, CLI, Studio, recordings).
- **Method:** asset- and entry-point-driven review. Each mitigation links to the code or test that implements it.
- **Status:** internal review only, including one adversarial code review (findings fixed; see T19, T20 and IMPLEMENTATION_STATUS). No external audit has been performed.

## 1. Assets

| Asset                                                        | Sensitivity                                 |
| ------------------------------------------------------------ | ------------------------------------------- |
| Upstream API keys (`Authorization`, `x-api-key`, query keys) | High: direct financial and account impact   |
| Prompts (request bodies)                                     | High: may contain personal or business data |
| Completions (response payloads)                              | Medium–High                                 |
| Upstream quota / billing                                     | Medium                                      |
| The developer's machine and local network                    | High                                        |

## 2. Trust boundaries and entry points

| Entry point                               | Who can reach it by default                            |
| ----------------------------------------- | ------------------------------------------------------ |
| Proxy data path (`/*`)                    | Processes on the same machine (loopback bind)          |
| Control API + Studio (`/__tokenfault/*`)  | Loopback peers with a loopback `Host` header only      |
| Upstream responses                        | The configured upstream (untrusted content)            |
| Recording files (`replay`, Studio import) | Anyone who can give the developer a file (untrusted)   |
| Web pages in the developer's browser      | Can send requests to `127.0.0.1` (CSRF, DNS rebinding) |
| CLI arguments and environment             | The local user                                         |

## 3. Threats and mitigations

| T1  | **Open proxy / SSRF**: the request chooses the upstream host                              | The upstream is fixed at startup. Absolute-form and `//host` targets are rejected. | T3  | **Network exposure**: bound to `0.0.0.0` by mistake                                       | Loopback default. | T4  | **DNS rebinding** against the control API or data path                                    | Control API: loopback peer and loopback `Host` header. | T7  | **Prompt/completion persistence**                                                         | Prompts are never captured (only model, stream flag, counts, size). | T8  | **Recording files readable by other users**                                               | Files are created with mode `0600` and `wx` (no overwrite). A directory the recorder creates gets `0700`; for an existing permissive directory the recorder logs a warning.                                                                                      | `recorder.ts`; `recording-static.test.ts`                                                                                                                                             |
| T9  | **Malicious recording files** (oversized, malformed, prototype pollution, path injection) | Size checked before parsing. Strict zod schema (unknown keys, including `__proto__`, rejected), bounded arrays and strings, monotonic timestamps, validated base64, id restricted to `[A-Za-z0-9_-]`. | T10 | **Path traversal** in Studio static serving                                               | Single percent-decode. NUL and backslash rejected. The resolved path and its realpath must stay in the root, so symlinks cannot escape. Regular files only.                                                                                                      | `static-files.ts`; `recording-static.test.ts`                                                                                                                                         |
| T11 | **Memory exhaustion** (huge events, endless streams, many sessions, slow subscribers)     | `maxEventBytes` (decoder discards and resyncs; framer flushes), per-session event/chunk/byte caps, `maxSessions` ring, bounded diagnostics and annotations, live-feed subscriber buffer cap, backpressure to upstream, request `bodyLimit`, recording size limit | `decoder.ts`, `framer.ts`, `stream-inspector.ts`, `session-store.ts`, `live-feed.ts`; tests in `sse-decoder.test.ts`, `stream-inspector.test.ts`, `proxy.test.ts` (backpressure, 413) |
| T12 | **Slow-loris / hung upstream**                                                            | Headers timeout (504), idle timeout, optional total timeout. Client disconnect aborts the upstream.                                                                                                                                                              | `proxy-handler.ts`; `proxy.test.ts` (AC-2.3, AC-2.5)                                                                                                                                  |
| T13 | **Unbounded fault parameters** (e.g. a 1-year delay via header)                           | Every numeric field is bounded (delays ≤ 10 min). Header profile ≤ 4 KiB. Strict objects.                                                                                                                                                                        | `faults/schema.ts`; `faults.test.ts`                                                                                                                                                  |
| T14 | **XSS** from untrusted stream content in the Studio                                       | React text nodes only (no `dangerouslySetInnerHTML`). Strict CSP (`script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`). `nosniff`, `X-Frame-Options: DENY`.                                                                                       | `JsonView.tsx`; `server.ts`; E2E CSP test                                                                                                                                             |
| T15 | **Terminal escape injection** via stream content printed by the CLI                       | All untrusted text goes through `sanitizeForTerminal` (C0/C1 controls escaped)                                                                                                                                                                                   | `output.ts`; `cli.test.ts`                                                                                                                                                            |
| T16 | **Downgrade / MITM to upstream**                                                          | Node's TLS verification is never disabled. There is no option to disable it.                                                                                                                                                                                     | `proxy-handler.ts` (default `https.request`)                                                                                                                                          |
| T17 | **Response splitting / header injection**                                                 | Request targets with control characters are rejected. Headers are forwarded through Node's validating `writeHead`. Hop-by-hop and `Connection`-listed headers are stripped.                                                                                      | `target.ts`, `headers.ts`; tests                                                                                                                                                      |
| T18 | **Spoofed TokenFault headers** from upstream                                              | All `x-tokenfault-*` response headers from upstream are dropped before the proxy adds its own                                                                                                                                                                    | `headers.ts`; `target-headers.test.ts`                                                                                                                                                |

| T19 | **Control-plane guard bypass via encoded or absolute-form paths** (`/%5F%5Ftokenfault/api/...` is percent-decoded by the router; `GET http://host/__tokenfault/...`) | A request counts as control-plane if the matched route, the raw path or the percent-decoded path carries the prefix. Absolute-form request targets are rejected with 400. _Found by the internal review and fixed._ | `server.ts` (`isControlRequest`); `proxy.test.ts` ("review regressions") |
| T20 | **Unexportable sessions**: upstream values outside recording bounds (huge `id`/`event`, status > 599) break export, replay and recording | `createRecording` clamps every upstream-controlled field to the schema bounds. The schema rejects values that would break SSE framing on replay, as well as invalid base64 or length mismatches. _Found by the internal review and fixed._ | `recording.ts`, `schema.ts`; `review-regressions.test.ts` |

## 4. Residual risks (accepted or open)

1. **Local multi-user machines.** Any local process can use the loopback proxy and read the control API, including
   in-memory completions. Mitigation available: `--no-capture-payloads`. An optional control-API token is planned.
2. **`--allow-remote`** exposes the data path (not the control plane) to the network. Anyone who can reach the port
   can send requests through it to the configured upstream. The proxy never injects credentials, so they must
   supply their own, but they consume upstream capacity through it. This option is meant for trusted networks only.
3. **DNS rebinding against the mock server.** The mock has no Host check. It holds no secrets and only produces
   synthetic data.
4. **Mock-only scenario delegation** forwards `x-tokenfault-scenario` to the upstream. A third-party provider
   would see that header name and value. It contains no secrets.
5. **Request bodies are buffered** (up to `maxRequestBodyBytes`, 20 MiB by default) before forwarding.
6. **Upstream response headers are forwarded** (minus hop-by-hop, HSTS, Alt-Svc and `x-tokenfault-*`), including
   `set-cookie`. They are not captured.
7. **Dependencies.** Runtime dependencies are `fastify` and `zod` (plus React in the Studio bundle). There is no
   automated dependency audit in CI yet (planned).
8. **No external audit or fuzzing campaign** beyond the property-style partition tests.
